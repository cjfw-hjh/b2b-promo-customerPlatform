# ASCII 와이어프레임 — 정성을 보여줘 (MVP)

## 문서 목적

이 문서는 아래 세 문서를 근거로, MVP 화면 9개(공통 인증 2개 + 영업사원 View 4개 + 팀장 View 3개)의 레이아웃을 텍스트(ASCII) 와이어프레임으로 정리한다.

- 화면 목록/파일명의 기준: `prompts/4-project-principle.md` (6번 섹션, 프론트엔드 디렉토리 구조)
- 각 화면의 기능 요구사항: `prompts/2-PRD.md`
- 화면에서 실제 오가는 내용 참고: `prompts/3-user-scenario.md`

픽셀 단위 정교한 디자인이 아니라, "이 화면에 어떤 영역이 있고 무엇이 배치되는지"만 보여주는 수준으로 작성했다. PRD/원칙 문서에 없는 화면·기능(대시보드, 통계, 알림센터, 설정 등)은 만들지 않았다.

**배경 동작이라 별도 화면이 없는 요구사항**: PRD 5.8(이메일 알림)과 5.2의 RULE-ORG-005(미가입 팀장 자동 연결)는 화면에 그려지는 요소가 아니라 순수 백그라운드 동작이다. 이메일 알림은 수신자의 별도 메일함에서 확인되는 것이지 이 앱 화면 안에 "알림 발송됨" 토스트를 띄우는 것은 PRD·사용자 시나리오 어디에도 없는 요구라 추가하지 않았다(넣었다면 그게 오히려 오버엔지니어링이다). 팀장 자동 연결도 가입 시점에 조용히 이뤄지는 데이터 매칭일 뿐이라 확인용 화면이 필요 없다 — 매칭 후에는 그냥 ManagedSalesLogListPage에 기존 영업일지가 자연스럽게 나타난다.

**박스 정렬에 대하여**: 이 문서의 모든 박스는 "한글 1자 = monospace 환경에서 영문/숫자 2자 폭"이라는 표준 가정 하에 폭을 계산해 맞췄고, 스크립트로 모든 코드블록의 좌우 테두리 정렬을 검증했다. 다만 실제 렌더링 폰트/뷰어에 따라 ±1~2칸 오차가 있을 수 있으므로 "대략적인 정렬" 수준으로 이해하면 된다.

## 공통 레이아웃 원칙 (한 번만 설명)

- 로그인 이후의 모든 화면은 **상단 네비게이션 바 + 본문 영역**의 2단 구조를 공유한다. 아래 각 화면의 와이어프레임은 상단 네비게이션 바를 매번 다시 그리지 않고, `[공통 네비게이션 바 - OO용]` 한 줄로만 표시한다. 실제 구성은 다음과 같다.
  - 좌측: 서비스명/로고
  - 우측 메뉴 (영업사원): 일지 작성 · 내 일지 조회 · 거래처 Know-how(P1) · 로그아웃
  - 우측 메뉴 (팀장): 팀원 일지 목록 · 내 코멘트 이력 · 로그아웃
  - 로그인 성공 시 `role` 값에 따라 두 메뉴 세트 중 하나로 자동 진입한다 (RoleGuard, UC-002).
- 회원가입/로그인 화면(인증 전)은 네비게이션 바가 없고, 중앙 정렬된 단일 폼만 존재한다.
- 본문 영역만 화면마다 달라지며, 이 문서의 각 와이어프레임은 그 본문 영역을 그린 것이다.

## 반응형(모바일) 원칙 (한 번만 설명, 문서 전체 공통)

PRD 6번/7번의 "데스크톱 우선 설계 + 모바일은 반응형 레이아웃으로만 대응, 접근성(a11y) 미고려" 원칙을 그대로 따른다. 별도의 `Mobile*` 화면·컴포넌트는 없으며, 동일 컴포넌트에 CSS 미디어 쿼리만 적용해 다음과 같이 "접힌다."

- 상단 네비게이션 바: 가로로 나열된 메뉴가 좁은 화면에서는 줄바꿈되거나 축약된 형태로 쌓인다.
- 표 형태 목록(영업일지 목록, 팀원 일지 목록, 코멘트 이력 등): 여러 컬럼이 가로로 나열된 표 대신, 한 항목의 컬럼들(거래처/영업형태/작성일/상태 등)이 세로로 쌓이는 카드형 리스트가 된다.
- 검색 조건 입력 행(기간/거래처/영업형태/키워드) 및 폼 입력 필드들도 한 줄씩 세로로 쌓인다.
- 코멘트 스레드는 폭만 좁아질 뿐 구조(코멘트 목록 → 입력창) 변화는 없다.
- 접근성(a11y)은 이번 MVP 범위에서 고려하지 않는다.

## 1. SignupPage — 회원가입

```text
+----------------------------------------------+
| 정성을 보여줘                                |
| 회원가입                                     |
| -------------------------------------------- |
|                                              |
| 사번         [______________]  (6자리)       |
| 이메일       [______________]                |
| 비밀번호      [______________]  (7자리 이상) |
| 역할         ( ) 영업사원   ( ) 팀장         |
|                                              |
| ※ 역할 = 영업사원 선택 시에만 아래 항목 노출 |
| 팀장 이메일    [______________]              |
|                                              |
| [ 회원가입 ]                                 |
|                                              |
| 이미 계정이 있으신가요? 로그인               |
+----------------------------------------------+
```

사번/이메일/비밀번호/역할 입력 필드와 역할이 '영업사원'일 때만 나타나는 팀장 이메일 입력란, 회원가입 버튼으로 구성된다. (PRD 5.1, 5.2 / RULE-AUTH-001~006, RULE-USER-001~002, RULE-ORG-001~004, RULE-ORG-006)

(PRD 4.2, 5.3~5.5 / RULE-CUSTOMER-001~002, RULE-LOG-001~002, RULE-LOG-004, RULE-STT-001~007, PRINCIPLE-ACTIVITY-001)

(PRD 5.4, 5.7, 5.11 / RULE-LOG-002~005, RULE-FEEDBACK-001~004, RULE-REPLY-001~005)

```text
|   | (아직 등록된 코멘트 없음) |                                       |
|   +---------------------------+                                       |
|                                                                       |
| 코멘트 입력 (팀장 본인만 작성 가능)                                   |
|   +-------------------------+  [ 등록 ]                               |
|   | 여기에 코멘트를 입력... |                                         |
|   +-------------------------+                                         |
|   ※ 최초 코멘트는 팀장부터 시작(RULE-FEEDBACK-002) - 입력은 항상 활성 |
+-----------------------------------------------------------------------+
```

영업일지 내용은 읽기 전용(팀장은 수정/삭제 권한 없음), 기존 코멘트/답변 스레드도 읽기 전용으로 표시된다. **팀장 본인만 작성 가능한 코멘트 입력창**은 최초 코멘트 여부와 무관하게 항상 활성화되어 있다(최초 코멘트는 반드시 팀장부터 시작하므로 입력 제약이 없음). 이 화면은 SalesLogDetailPage와 동일한 영업일지·코멘트 스레드를 팀장 시점에서 보여주는 화면이며, 영업일지 자체의 수정/삭제 권한이 팀장에게 없다는 점은 SalesLogDetailPage(작성자만 수정/삭제 가능)와 일관된다. (PRD 5.6, 5.7 / UC-007, UC-008, RULE-ORG-008, RULE-FEEDBACK-001~004)
